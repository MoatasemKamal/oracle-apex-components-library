# Theme Styles (Universal Theme styles)

`theme-styles/` holds **Universal Theme styles**: whole-app looks that sit beside Vita, Vita Dark
and Redwood Light. A developer sets one as current in Theme Roller or Shared Components > Themes >
Styles, and can let end users pick it (Customization). Because every component and template in this
library reads the same `--ut-*` variables, a style restyles native APEX and the library together.

## Folder layout

```
theme-styles/<slug>/
  style.json                 metadata
  amc-style-<slug>.css       the style (variables + Universal Theme refinements)
  README.md, dist/           generated by tools/build-styles.mjs (never edit)
```

```bash
node tools/build-styles.mjs [--only <slug>]      # validate (incl. WCAG contrast) + emit
node tools/preview-styles.mjs [--only <slug>]    # preview/styles[-slug].html on a UT mock page
node tools/apexlang-check.mjs --apexlang <root>  # formatter + grammar audit (styles included)
```

## style.json

| Field | Notes |
|---|---|
| `name` | e.g. `AMC Aurora`; no `( ) { }` or colon |
| `staticId` | `AMC_STYLE_<NAME>`; never change after release |
| `version` | semver |
| `base` | built-in style CSS it layers on: `vita`, `vita-dark`, `vita-slate`, `redwood` |
| `scheme` | `light`, `dark`, or `auto` (follows the operating system) |
| `description`, `helpText`, `keywords` | as for templates |
| `cssClasses` | optional classes APEX adds to the page body for this style |
| `endUserCanPick` | default true |

## The CSS

1. A `:root { ... }` block that sets at least: `--ut-body-background-color`,
   `--ut-body-text-color`, `--ut-component-background-color`, `--ut-component-text-default-color`,
   `--ut-component-text-muted-color`, `--ut-component-border-color`, `--ut-component-border-radius`,
   `--ut-link-text-color`, `--ut-palette-primary` (+ `-contrast`), `--ut-palette-success`,
   `--ut-palette-warning`, `--ut-palette-danger`, `--ut-palette-info` (their `-contrast` values are
   recommended), and ideally `--ut-component-box-shadow`, `--ut-focus-outline-color`,
   `--ut-header-background-color`, `--ut-header-text-color`, `--ut-nav-background-color`.
   Use literal colors (hex or rgb) for these so the build can compute contrast.
2. Refinements for Universal Theme parts that variables do not reach, using real UT classes
   (`.t-Header`, `.t-Body-nav`, `.t-TreeNav`, `.t-Region`, `.t-Button--hot`, `.t-Report`,
   `.t-Form-*`, `.t-Alert`, `.t-Badge`, `.a-IRR-*`, `.a-CardView-*`...). Keep them few and robust:
   color, background, border, radius, shadow, font. Never change layout, sizes or display.
3. `scheme: auto` styles redefine the palette inside `@media (prefers-color-scheme: dark)`.
4. Fonts: system stacks only (no `@import`, no external `url()`; apps often run under a strict
   CSP or offline). A style may name an optional web font first in the stack and document it.
5. Any animation needs a reduced-motion override; add `@media (forced-colors: active)` fixes for
   gradients and shadows that carry meaning; mirror direction-specific details for RTL
   (`[dir="rtl"]` or logical properties).

## Quality gate (enforced by the build)

- WCAG AA: body text, region text, muted text and links at least 4.5:1 on their backgrounds;
  primary-contrast on primary 4.5:1; primary on the region background 3:1 (UI components).
  Auto styles are checked in both schemes.
- Required variables present, no `@import` / external URLs, reduced-motion when animating.

## Status

The preview is a **mock** of a Universal Theme page (real UT class names, simplified CSS). The
base CSS file names (`Vita`, `Vita-Dark`, `Vita-Slate`, `Redwood-Light`), the
`create_theme_style` parameters and the APEXlang `style` placement are best knowledge and must be
confirmed on the target APEX release; apply each style to a real app before production.
